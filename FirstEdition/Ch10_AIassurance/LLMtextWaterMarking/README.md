## Idea and Code




# LLM Text Watermarking

## 1. Introduction

Large Language Models (LLMs) generate text by predicting the probability of the next token.

**Text watermarking** introduces a hidden statistical pattern into the generated text by slightly modifying token-selection probabilities.

The goal is to distinguish text generated by a watermarked model from ordinary text.

Unlike an image watermark, there is no visible symbol or signature.

## 2. Basic Idea

Suppose an LLM has six possible words:

| Word | Original probability |
|---|---:|
| cat | 0.30 |
| dog | 0.25 |
| bird | 0.20 |
| fish | 0.10 |
| horse | 0.10 |
| mouse | 0.05 |

The probabilities sum to 1.

We divide the vocabulary into two groups:

- Green list: cat, bird, horse
- Red list: dog, fish, mouse

The watermarking algorithm increases the probability of selecting green-list words.

For example, we multiply their original probabilities by 2, then normalize so the probabilities sum to 1 again.

| Word | Original | Watermarked |
|---|---:|---:|
| cat | 0.30 | 0.3750 |
| dog | 0.25 | 0.1563 |
| bird | 0.20 | 0.2500 |
| fish | 0.10 | 0.0625 |
| horse | 0.10 | 0.1250 |
| mouse | 0.05 | 0.0313 |

Green words become more likely, but they are not guaranteed to appear.

## 3. Python Example

Run in Google Colab or any Python environment with NumPy installed.

```python
import numpy as np

np.random.seed(42)

# Vocabulary and original probabilities
words = ["cat", "dog", "bird", "fish", "horse", "mouse"]
probs = np.array([0.30, 0.25, 0.20, 0.10, 0.10, 0.05])

# Secret green list (fixed for this simple demonstration)
green = {"cat", "bird", "horse"}

# Watermark: boost probabilities of green words
wm_probs = np.array([
    p * 2 if w in green else p
    for w, p in zip(words, probs)
])
wm_probs /= wm_probs.sum()

# Generate 100 tokens
normal = np.random.choice(words, 100, p=probs)
watermarked = np.random.choice(words, 100, p=wm_probs)

# Count green tokens
def detect(tokens):
    count = sum(w in green for w in tokens)
    return count, count / len(tokens)

print("Original probabilities:", probs)
print("Watermarked probabilities:", wm_probs)

print("\nNormal:", detect(normal))
print("Watermarked:", detect(watermarked))
```

## 4. Understanding the Code

The most important lines are:

```python
normal      = np.random.choice(words, 100, p=probs)
watermarked = np.random.choice(words, 100, p=wm_probs)
```

The parameter `p` specifies the probability of selecting each word.

- Normal generation uses the original probabilities.
- Watermarked generation uses the modified probabilities.

The watermark is introduced during token selection, not after the text has been generated.

## 5. Detecting the Watermark

The function `detect()` counts how many generated tokens belong to the green list.

For our example:

- Original probability of selecting a green token = 0.60
- Watermarked probability of selecting a green token = 0.75

Therefore, out of 100 generated tokens, we expect approximately:

| Generator | Expected green tokens |
|---|---:|
| Normal | 60 |
| Watermarked | 75 |

Actual results vary because token selection is random.

A higher green-token frequency provides evidence of watermarking.

However, this simple frequency comparison is not sufficient for reliable detection. A real detector uses a statistical test and accounts for the expected green-token frequency.

## 6. Simple Mathematics

### Original probabilities

The sum of all probabilities must equal 1:

$$
\sum_i p_i = 1
$$

### Watermarked probabilities

Multiply green-token probabilities by a factor of 2:

$$
w_i = 2p_i \quad \text{(green tokens)}
$$

For red tokens:

$$
w_i = p_i
$$

Normalize the probabilities:

$$
p'_i = \frac{w_i}{\sum_j w_j}
$$

Example for the word cat:

$$
p'(cat) = \frac{2(0.30)}{1.60} = 0.375
$$

The probability of cat increases from 30% to 37.5%.

## 7. How Real LLM Watermarking Works

Our example uses a fixed green list.

Real watermarking algorithms, such as the method proposed by Kirchenbauer et al. (2023), are more sophisticated:

1. The LLM predicts probabilities for the next token.
2. A secret key and preceding tokens determine a pseudorandom green list.
3. Green-token probabilities are increased.
4. The LLM samples the next token.
5. The process repeats for every generated token.
6. A detector reconstructs the green lists and performs a statistical test.

The watermark is therefore distributed across many tokens.

## 8. Limitations

- Short texts may not contain enough evidence.
- Editing or paraphrasing can weaken a watermark.
- False positives are possible.
- Not all AI-generated text is watermarked.
- Watermark detection is statistical evidence, not absolute proof.

## Statistical Detection of LLM Watermarks Using Z-Scores

### Why Do We Need a Z-Score?

Previously, we introduced a watermark by increasing the probability of selecting green-list tokens.

However, simply counting green tokens is not enough. Even normal text contains green tokens by chance.

The **Z-score** measures how much the observed number of green tokens differs from what we would expect without watermarking, expressed in standard deviations.

This is conceptually similar to chance correction in metrics such as Cohen's kappa, although the Z-score measures statistical deviation rather than agreement.

### Z-Score Equation

$$
Z = \frac{G - np}{\sqrt{np(1-p)}}
$$

Where:

- `G` = observed number of green tokens
- `n` = total number of generated tokens
- `p` = probability of a green token without watermarking
- `np` = expected number of green tokens

### Example: 100 Tokens

Suppose:

- Total tokens = 100
- Expected green-token probability = 0.60
- Observed green tokens = 75

The expected number of green tokens is:

$$
100(0.60) = 60
$$

The Z-score becomes:

$$
Z = \frac{75 - 60}{\sqrt{100(0.60)(0.40)}} = 3.06
$$

**Interpretation:** We observed 75 green tokens instead of the expected 60. This is 3.06 standard deviations above expectation, providing statistical evidence of watermarking.

### Experiment: Does Text Length Matter?

Using the Python code above, we compare three scenarios:

1. Short text: 100 tokens
2. Medium text: 1,000 tokens
3. Long text: 10,000 tokens

For each scenario, we generate both normal and watermarked text, calculate their Z-scores, and plot the results.

| Number of tokens | Expected normal Z-score | Expected watermarked Z-score |
|---|---:|---:|
| 100 | 0 | 3.06 |
| 1,000 | 0 | 9.68 |
| 10,000 | 0 | 30.62 |

These are theoretical expected values. The actual simulated results vary because token selection is random.

### Understanding the Plot

- **X-axis:** Number of generated tokens (logarithmic scale).
- **Y-axis:** Z-score measuring deviation from the expected green-token count.
- **Normal text:** Z-scores fluctuate around zero.
- **Watermarked text:** Z-scores tend to increase as the number of tokens grows.

The watermark becomes statistically easier to detect with longer text because the accumulated green-token bias becomes more distinguishable from random fluctuations.

Under the assumptions of our example, the expected watermarked Z-score increases approximately with the square root of the number of tokens.

### Important Observation

A high Z-score does not provide absolute proof of watermarking. It indicates that the observed green-token frequency would be unusual under the assumed normal-generation model.

Our example uses a fixed green list and independent token sampling. Real LLM watermarking algorithms typically use changing green lists and more sophisticated statistical detection.






```


import numpy as np
import matplotlib.pyplot as plt

np.random.seed(42)

words = ["cat", "dog", "bird", "fish", "horse", "mouse"]
probs = np.array([0.30, 0.25, 0.20, 0.10, 0.10, 0.05])

green = {"cat", "bird", "horse"}

# Boost green-token probabilities
wm_probs = np.array([
    p * 2 if w in green else p
    for w, p in zip(words, probs)
])
wm_probs /= wm_probs.sum()

# Expected green probability without watermark
p_green = sum(p for w, p in zip(words, probs) if w in green)

def z_score(tokens):
    n = len(tokens)
    G = sum(w in green for w in tokens)

    return (G - n * p_green) / np.sqrt(n * p_green * (1 - p_green))

# Compare three scenarios
token_counts = [100, 1000, 10000]
normal_z = []
watermarked_z = []

for n in token_counts:

    normal = np.random.choice(words, n, p=probs)
    watermarked = np.random.choice(words, n, p=wm_probs)

    zn = z_score(normal)
    zw = z_score(watermarked)

    normal_z.append(zn)
    watermarked_z.append(zw)

    print(f"\nNumber of tokens: {n}")
    print(f"Normal:      Z = {zn:.2f}")
    print(f"Watermarked: Z = {zw:.2f}")

# Plot the results
plt.figure(figsize=(9, 5))

plt.plot(token_counts, normal_z, 'o-', label="Normal")
plt.plot(token_counts, watermarked_z, 's-', label="Watermarked")

plt.axhline(0, color='gray', linestyle='--', linewidth=1)

plt.xlabel("Number of Tokens")
plt.ylabel("Z-score")
plt.title("LLM Watermark Detection: Z-score vs. Text Length")
plt.legend()
plt.grid(True)
plt.xscale("log")
plt.xticks(token_counts, ["100", "1,000", "10,000"])

plt.show()



```

## Secret Key Approach




## Secret-Key LLM Watermarking

### 1. Why Do We Need a Secret Key?

In our previous example, the green list was fixed:

```python
green = {"cat", "bird", "horse"}
```

This is a weakness because someone who discovers the green list could potentially manipulate the generated text to remove the watermark.

A more sophisticated approach uses a **secret key** to generate different green lists as text is produced.

The key idea is simple:

**The green list changes depending on the previous token and a secret key.**

For example:

| Previous Token | Possible Green List |
|---|---|
| cat | dog, bird, mouse |
| dog | cat, fish, horse |
| bird | dog, fish, mouse |

These are illustrative lists. The actual lists are generated by the algorithm.

### 2. How Does the Secret Key Work?

The secret key is a private value known to the watermark generator and authorized detector.

For each new token:

1. Take the previous token.
2. Combine it with the secret key.
3. Apply a cryptographic hash function (SHA-256).
4. Use the hash results to select the next green list.
5. Increase the probabilities of green-list tokens.
6. Sample the next token.

The process repeats as the text is generated.

**Important:** The secret key does not encrypt the text. It controls the hidden statistical pattern introduced during generation.

### 3. The Role of SHA-256

SHA-256 is a cryptographic hash function that produces a 256-bit output.

In our Python example:

```python
message = f"{key}:{previous_word}:{word}"
score = hashlib.sha256(message.encode()).hexdigest()
```

Each candidate word receives a hash score.

The words with the three smallest hash scores become the green list.

Changing the previous word or the secret key changes the hash scores and can change the green list.

This makes the green list deterministic for someone who knows the key, but difficult to predict without it.

### 4. Watermark Detection

The detector receives the generated text and uses the secret key to reconstruct the green list at each token position.

It counts how many observed tokens belong to their corresponding green lists.

The detector then calculates a Z-score:

$$
Z = \frac{G-E}{\sqrt{V}}
$$

Where:

- `G` = observed number of green tokens
- `E` = expected number of green tokens without watermarking
- `V` = variance of the expected green-token count

In our example, the expected probability of a green token changes with the green list because the original word probabilities are unequal.

Therefore, the code calculates the expected count and variance at every token position.

A high positive Z-score indicates that green tokens appeared more frequently than expected under normal generation.

### 5. Experiment: Does the Secret Key Matter?

We compare three scenarios:

| Scenario | Description |
|---|---|
| Normal text | Generated without watermarking |
| Watermarked, correct key | Generated with watermarking and detected using the correct secret key |
| Watermarked, wrong key | Same watermarked text, but detected using an incorrect secret key |

The Python code generates 1,000 tokens and calculates the Z-score for each scenario.

### 6. Understanding the Plot

The bar chart compares the Z-scores of the three scenarios.

**Normal text:** The Z-score should generally be near zero because the token-selection probabilities have not been modified.

**Watermarked text with the correct key:** The Z-score should be substantially positive because the detector reconstructs the same green lists used during generation.

**Watermarked text with the wrong key:** The Z-score should generally be much lower because the detector reconstructs different green lists.

The red dashed line at Z = 3 is an illustrative statistical detection threshold.

A Z-score above 3 suggests that the observed green-token frequency is unusually high under the assumed normal-generation model.

However, statistical detection is not absolute proof. False positives and false negatives remain possible.

### 7. Why Is This Better Than a Fixed Green List?

| Fixed Green List | Secret-Key Green List |
|---|---|
| Same green words throughout | Green words change with token history |
| Easier to discover | Harder to predict without the key |
| Simple to implement | Requires hashing and key management |
| Detector checks one fixed list | Detector reconstructs the list at each position |

The secret-key approach makes the watermark more difficult to identify and manipulate without knowledge of the key.

### 8. Connection to Cryptography

This example demonstrates several important cybersecurity concepts:

- **Secret keys:** Only authorized parties know the key.
- **Cryptographic hashing:** SHA-256 generates deterministic values from inputs.
- **Pseudorandom selection:** Hash scores determine changing green lists.
- **Statistical authentication:** The detector tests for a hidden pattern associated with the key.

Unlike a digital signature, a statistical watermark does not provide a cryptographic guarantee of authenticity or integrity.

**Key takeaway:** Secret-key watermarking introduces a changing statistical pattern into generated text. A detector with the correct key can reconstruct that pattern and test for its presence, while someone without the key has a harder time identifying it.




```

import numpy as np
import hashlib

rng = np.random.default_rng(42)

words = ["cat", "dog", "bird", "fish", "horse", "mouse"]
probs = np.array([0.30, 0.25, 0.20, 0.10, 0.10, 0.05])

secret_key = "my_secret_key"

# Generate a green list using the secret key and previous word
def get_green_list(previous_word, key):
    scores = []

    for word in words:
        message = f"{key}:{previous_word}:{word}"
        score = hashlib.sha256(message.encode()).hexdigest()
        scores.append((score, word))

    scores.sort()
    return {word for score, word in scores[:3]}


# Generate text (normal or watermarked)
def generate(n, key, watermark=False):
    tokens = []
    previous_word = "START"

    for _ in range(n):
        p = probs.copy()

        if watermark:
            green = get_green_list(previous_word, key)

            for i, word in enumerate(words):
                if word in green:
                    p[i] *= 2

            p /= p.sum()

        word = rng.choice(words, p=p)
        tokens.append(word)
        previous_word = word

    return tokens


# Detect watermark using the secret key
def detect(tokens, key):
    previous_word = "START"
    observed = 0
    expected = 0
    variance = 0

    for word in tokens:
        green = get_green_list(previous_word, key)

        if word in green:
            observed += 1

        # Expected green probability without watermark
        p_green = sum(
            p for w, p in zip(words, probs) if w in green
        )

        expected += p_green
        variance += p_green * (1 - p_green)

        previous_word = word

    z = (observed - expected) / np.sqrt(variance)
    return z


# Compare normal and watermarked text
normal = generate(1000, secret_key, watermark=False)
watermarked = generate(1000, secret_key, watermark=True)

print("Normal Z-score:     ", round(detect(normal, secret_key), 2))
print("Watermarked Z-score:", round(detect(watermarked, secret_key), 2))

# Try detecting with the WRONG secret key
print("Wrong key Z-score:  ",
      round(detect(watermarked, "wrong_key"), 2))

# Show how the green list changes
print("\nGreen list after 'cat':", get_green_list("cat", secret_key))
print("Green list after 'dog':", get_green_list("dog", secret_key))




import matplotlib.pyplot as plt

# Compare three scenarios
normal = generate(1000, secret_key, watermark=False)
watermarked = generate(1000, secret_key, watermark=True)

scores = [
    detect(normal, secret_key),
    detect(watermarked, secret_key),
    detect(watermarked, "wrong_key")
]

labels = [
    "Normal Text",
    "Watermarked\nCorrect Key",
    "Watermarked\nWrong Key"
]

# Plot
plt.figure(figsize=(9, 5))

bars = plt.bar(labels, scores,
               color=["gray", "green", "orange"])

plt.axhline(0, color="black", linestyle="--")
plt.axhline(3, color="red", linestyle="--",
            label="Z = 3 threshold")

plt.ylabel("Z-score")
plt.title("Secret-Key LLM Watermark Detection")
plt.legend()
plt.grid(axis="y", alpha=0.3)

for bar, score in zip(bars, scores):
    plt.text(
        bar.get_x() + bar.get_width()/2,
        score + (0.2 if score >= 0 else -0.4),
        f"{score:.2f}",
        ha="center"
    )

plt.show()




```
